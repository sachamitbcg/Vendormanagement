Vendor Risk & Onboarding Screener

Screens every new vendor against the existing vendor master, uses AI (Anthropic Claude) to recommend a risk tier with a plain-English rationale, and keeps a human reviewer in control of every decision.

React (Vite) FastAPI SQLite + Alembic Anthropic Claude JWT auth

The problem

Procurement onboards 30–50 vendors a quarter. Each needs a compliance screen — duplicate detection (same bank account or ABN) and a document-completeness check — today done manually by one analyst cross-referencing spreadsheets.

What this does

  • Deterministic engine finds exact & partial duplicates + missing fields.
  • Claude turns those findings into a risk tier, rationale & reviewer checklist.
  • Reviewer overrides / approves; every decision is logged for override-rate tracking.
  • Falls back to rules if AI is unavailable — never auto-approves.

How a vendor gets screened

1Analyst opens the onboarding form.
2Form posted & validated.
3Engine checks vendor master: exact / partial / bank match.
4Findings + form handed to the AI gateway.
5Claude called with a versioned prompt.
6JSON reply (tier, anomalies, checklist) stored on the vendor.
7Reviewer approves or overrides the tier.
8Every AI decision & override written to the audit log.

Solution architecture

Frontend → FastAPI (Auth · Screening Engine · Audit Logger) → LLM Gateway → Claude, over a SQLite database.
